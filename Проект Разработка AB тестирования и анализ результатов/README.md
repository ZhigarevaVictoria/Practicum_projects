# Разработка A/B-тестирования и анализ результатов


## 📊 Обзор проекта

**Цель:** Рассчитать параметры A/B-теста для проверки нового алгоритма рекомендаций в развлекательном приложении, оценить корректность его проведения и проанализировать результаты эксперимента.

**Дата выполнения:** апрель 2026


## 📁 Данные

Проект использует три таблицы:

### Исторические данные (`sessions_project_history.csv`, 134 039 записей, 11 полей)
- `user_id` — идентификатор пользователя
- `session_id` — идентификатор сессии
- `session_date` — дата сессии
- `session_start_ts` — дата и время начала сессии
- `install_date` — дата установки приложения
- `session_number` — порядковый номер сессии
- `registration_flag` — зарегистрирован ли пользователь
- `page_counter` — количество просмотренных страниц
- `region` — регион пользователя (CIS, EU, MENA)
- `device` — тип устройства (Android, iPhone, PC, Mac)

### Данные первого дня теста (`sessions_project_test_part.csv`, ~3 000 записей)
- Те же поля + `test_group` — тестовая группа (A / B)

### Данные полного теста (`sessions_project_test.csv`, 100 005 записей)
- Те же поля + `test_group` — тестовая группа (A / B)


## 📈 Этапы анализа

### 1. Работа с историческими данными (EDA)

**Загрузка и знакомство с данными**
- Изучение структуры таблиц и логики заполнения полей
- Выявление пользователя с наибольшим количеством сессий (10 сессий)

**Анализ регистраций**
- Расчёт числа уникальных и зарегистрированных пользователей по дням
- Построение графиков динамики: общее число пользователей, число зарегистрированных, доля регистраций
- **Вывод:** доля зарегистрированных пользователей стабильно низкая (~0.5–1%), нет выраженных трендов

**Анализ числа просмотренных страниц**
- Построение распределения первых сессий по количеству страниц
- **Результат:** пик на 3 страницах (50 939 сессий), среднее значение — 3.01 страницы

**Доля успешных сессий (good_session)**
- Создание признака `good_session = (page_counter ≥ 4)`
- Построение графика доли успешных первых сессий по дням
- **Результат:** средняя доля — 31.08%, диапазон колебаний 29.7%–33.2% — метрика стабильна

### 2. Подготовка к тесту

**Расчёт размера выборки**
- Параметры: α = 0.05, мощность = 0.8, MDE = 3% (абсолютный прирост 0.009)
- Базовый уровень успешных сессий: 30%
- **Результат:** необходимый размер выборки — 41 041 пользователь на группу

**Расчёт длительности теста**
- Средний дневной трафик: ~9 907 уникальных пользователей
- **Результат:** требуемая длительность теста — 9 дней

### 3. Мониторинг A/B-теста

**Проверка распределения пользователей (первые 3 дня)**
- Группа A: 1 477 пользователей, группа B: 1 466 → разница 0.74%

**Проверка пересечений**
- Пересечений между группами A и B нет ✅

**Равномерность по устройствам и регионам**
- Распределение типов устройств и регионов практически идентично ✅

**Вывод:** A/B-тест проходит корректно, сплитование работает без нарушений

### 4. Анализ результатов A/B-теста

**Целевая метрика:** доля успешных первых сессий (good_session = 1 при просмотре ≥4 страниц)

**Результаты теста:**
- Группа A (контроль, старый алгоритм): 15 162 первых сессий, доля успеха — **31.57%**
- Группа B (тест, новый алгоритм): 15 416 первых сессий, доля успеха — **31.47%**
- Разница (B − A) = **−0.10 п.п.** (отрицательная)

**Статистический тест (односторонний z-тест):**
- z-статистика = −0.1977
- p-value = 0.5784

**Вывод:** p-value > 0.05 — разница статистически незначима. Новый алгоритм не показал улучшения целевой метрики.

**Ограничение анализа:** фактический размер выборки (~15 тыс.) в 2.7 раза меньше требуемого (41 тыс.), что снижает мощность теста.

## 💡 Рекомендации для бизнеса

1. **Техническая часть теста выполнена корректно** — сплитование работает без нарушений, группы сбалансированы.

2. **Новый алгоритм не показал статистически значимого улучшения** целевой метрики (доля успешных первых сессий). Фактическая разница отрицательна (−0.10 п.п.).

3. **Тест обладает недостаточной мощностью** из-за недобора выборки (15 тыс. вместо 41 тыс.). Это снижает способность теста обнаружить реальный эффект.

4. **Рекомендации:**
   - Продолжить тест до набора требуемого объёма выборки (ещё ~25 тыс. пользователей на группу)
   - Либо пересмотреть MDE в сторону увеличения (например, до 2–3 процентных пунктов), что снизит требования к размеру выборки
   - Дополнительно проанализировать прокси-метрики (среднее число страниц, средняя длительность сессии) и барьерные метрики (конверсия в регистрацию, удержание)
